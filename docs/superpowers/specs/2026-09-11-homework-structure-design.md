# MATLAB 作业项目结构设计

日期：2026-09-11
状态：**已确认并实施**（2026-09-11）—— 在「单文件双用」之上，采用**一作业一目录**做隔离

## 背景

4–5 道 MATLAB 基础作业，每道题含 **要求 / 思考 / 提高** 三部分。题目已转成 markdown
（尚未提供内容）。需要先定下一套文件结构，让后续每道题都能直接往里放，不返工。

两个已知约束：

- 交付形式 **两种都要**：普通 `.m` 脚本 + Live Script
- 「思考部分」是**文字论述**，不是代码题 → 需要非代码落点

## 核心决策：单文件双用（方案 A）

不维护两份文件，只写一份 `.m`，同时充当可执行脚本与 Live Script。

依据是下面的实测结论，不是推断。

### 实测验证记录

| 验证项 | 命令 | 结果 |
|---|---|---|
| `%[text]` 行是合法 MATLAB 注释 | `matlab -batch "run('/tmp/hw_live_probe.m')"` | 正常执行，无语法错误 |
| 同一文件可当 Live Script | Live Code 规范 `guidelines://plain-text-live-code` | `%[text]` / `%%` / `%[appendix]` 格式成立，R2025a+ 支持 |
| 未加 `;` 的表达式会输出 | 同上，`y = sin(x)` | 打印 `y = 0 1.0000 0.0000 -1.0000 -0.0000` |
| `-batch` 退出码可用于提交门禁 | 同上，`echo $?` | `exit_code=0` |
| `addpath` 指向不存在的目录 | MCP `evaluate_matlab_code` | **抛警告**（非异常）：`名称不存在或不是目录` |
| `.gitkeep` 是否被忽略 | 读 `.gitignore` | 未忽略，可用于占位空目录 |
| MATLAB 版本 | `version` | 25.2.0.2998904 (R2025b) |

### 目录隔离的补充实测（2026-09-11 迁移时）

| 验证项 | 做法 | 结果 |
|---|---|---|
| 同目录函数无需 `addpath` | 先 `rmpath` 清掉仓库路径，确认 `exist('bounceBall','file') == 0` | 再跑脚本仍成功 → 同目录解析成立，**假阳性已排除** |
| 跨工作目录仍成立 | `cd('/tmp')` 后 `run('<绝对路径>/hw01_bouncingBall.m')` | 跑通，`3.1250` / `293.7500` 与迁移前一致 |
| 产物路径跟着迁移 | 删掉 png 后重跑 | 图在 `hw01-bouncingBall/outputs/` 重新生成，顶层 `outputs/` 保持为空 |

**已知陷阱（未完全隔离变量，仅记录现象）**：脚本内嵌本地函数（local function）与
`%[appendix]` 元数据块共存时，`openAndSave` 生成的 `.mlx` 会损坏（372 / 660 字节，
回读报「无法打开或加载编辑器」）；而不带 `%[appendix]` 的版本可正常往返并执行。
本方案不依赖本地函数（函数是独立 `.m`），暂不受影响。将来若要改本地函数，先重测这一点。

`addpath` 那条决定了一件事：**`functions/` 必须真实存在**，否则每次跑脚本都会刷一条警告。

### 代价（已知并接受）

Live Code 规范要求：正文不用 `fprintf`/`disp` 输出文字，改用「不加分号的表达式」显示值；
`%[text]` 每段写成单行。这会牺牲一点纯脚本的书写习惯，换掉两份文件不同步的风险。

## 目录结构（2026-09-11 迁移后）

顶层只剩作业目录与文档。`scripts/` `problems/` `notes/` `outputs/` 这类**按类型分的
公共目录已废除** —— 它们让「哪些文件属于作业一」只能靠文件名前缀猜，而且 `functions/`
会变成所有作业的混合池。

```
matlab_test/
├── CLAUDE.md
├── docs/superpowers/specs/       # 设计文档（本文件）
└── hw01-bouncingBall/            # 一份作业 = 一个自包含目录
    ├── problem.md                # 题目原文，只读参考
    ├── hw01_bouncingBall.m       # 可执行脚本（= 交付物）
    ├── bounceBall.m              # 该作业专用函数，与脚本同目录
    ├── notes.md                  # 思考题论述、推导、踩坑记录
    └── outputs/hw01.png          # 脚本导出的图，重跑即刷新
```

**不建这些**（YAGNI）：

- `livescripts/` —— 方案 A 下没有第二份文件
- `tests/` —— 基础作业靠 `-batch` 退出码 + 与手算/参考答案比对，不引测试框架
- `data/` —— 脚本自包含，除非某道题本身要求读外部数据
- 顶层共享 `functions/` —— 跨作业复用真出现时再建，不提前

## 每道题的工作流

1. 新建作业目录 `hw<NN>-<关键词>/`
2. 题目原文落到该目录的 `problem.md`
3. 脚本写到该目录，按 Live Code 格式书写；该作业专用函数与脚本同级
4. 跑通验证：`"$MATLAB" -batch "run('hw<NN>-<关键词>/hw<NN>_<行为名>.m')"`，退出码 0 才算数
5. 思考部分写进同目录 `notes.md`
6. 跑通即提交（粒度见 `.claude/rules/git.md`）

## 切分粒度

**默认一题一脚本**，用 `%%` 分节对应 要求 / 思考 / 提高。

例外：某道题的某一部分确实庞大、或需要独立可跑时，才拆成多个脚本。
具体留到读题时判断。

## 脚本命名（已定）

`hw<NN>_<行为名>.m`（例：`hw01_bouncingBall.m`），已写进 CLAUDE.md 的「脚本约定」。

保留 `hw<NN>_` 前缀的理由：作业目录名已含编号，但脚本被单独打开或拷走时，前缀仍能
自我标识。目录内不存在同名冲突，代价只是一个前缀。
