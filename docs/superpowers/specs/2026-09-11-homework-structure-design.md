# MATLAB 作业项目结构设计

日期：2026-09-11
状态：**已实施** —— 一作业一目录；脚本为**普通 `.m`**，不使用 Live Script 形态

## 背景

4–5 道 MATLAB 基础作业，每道题含 **要求 / 思考 / 提高** 三部分。需要先定下一套文件结构，
让后续每道题都能直接往里放，不返工。

两个约束：

- 使用者的操作是**在编辑器里点运行**：命令窗口出结果，图表弹窗
- 「思考部分」是**文字论述**，不是代码题 → 需要非代码落点

## 核心决策：普通 `.m` 脚本，不要 Live Script

脚本写成连续的普通 `.m`：不出现 `%[text]` / `%[appendix]` / `%[output:*]` 等 Live Code
标记，也不用 `%%` 分节 —— 从第一行到最后一行是连续代码。

返回值用 `fprintf` 带标签打印，图表用 `figure` 弹窗，**脚本本身不写文件**
（不导出 png、不存 .mat）。

### 历史：曾采用「单文件双用」（方案 A），2026-09-11 废弃

早期方案是让同一个 `.m` 既当可执行脚本、又当 Live Script（靠 `%[text]` 等标记），
目的是不维护两份文件，替代掉「Live Script 和 .m 两份不同步」的风险。

2026-09-11 使用者明确「不需要 Live Script 形态，我的需求就是普通 `.m` 文件，然后点击运行，
弹出运行结果的图表」，方案废弃，hw01 已改写。

废弃的实测收益：

| 项目 | 方案 A | 改为普通 `.m` 后 |
|---|---|---|
| 文件大小 | 259 694 字节 | 2 635 字节 |
| 行数 | 92 | 56 |

膨胀来自 Live Editor 会把运行结果写回成 `%[output:*]`，图片存成内嵌 base64 ——
这也是 git 工作区会「无故变脏」的原因。方案 A 的另一个代价是**书写受限**：
Live Code 规范禁止用 `fprintf`/`disp` 显示文字，只能靠「不加分号的表达式」隐式回显。

**不要再引入 Live Script 形态**，除非使用者重新要求。

## 目录结构

顶层只剩作业目录与文档。`scripts/` `problems/` `notes/` `outputs/` 这类**按类型分的
公共目录已废除** —— 它们让「哪些文件属于作业一」只能靠文件名前缀猜，而且 `functions/`
会变成所有作业的混合池。

```
matlab_test/
├── CLAUDE.md
├── docs/superpowers/specs/       # 设计文档（本文件）
└── hw01-bouncingBall/            # 一份作业 = 一个自包含目录
    ├── problem.md                # 题目原文，只读参考
    ├── hw01_bouncingBall.m       # 可执行脚本（点运行即出结果）
    ├── bounceBall.m              # 该作业专用函数，与脚本同目录
    └── notes.md                  # 思考题论述、推导、踩坑记录
```

**不建这些**（YAGNI）：

- `outputs/` —— 脚本不写文件，产物就是弹出来的图形窗口
- `livescripts/` —— 不用 Live Script，没有第二份文件
- `tests/` —— 基础作业靠 `-batch` 退出码 + 与手算/参考答案比对，不引测试框架
- `data/` —— 脚本自包含，除非某道题本身要求读外部数据
- 顶层共享 `functions/` —— 跨作业复用真出现时再建，不提前

## 每道题的工作流

1. 新建作业目录 `hw<NN>-<关键词>/`
2. 题目原文落到该目录的 `problem.md`
3. 脚本写到该目录，按普通 `.m` 写；该作业专用函数与脚本同级
4. 跑通验证：`"$MATLAB" -batch "run('hw<NN>-<关键词>/hw<NN>_<行为名>.m')"`，退出码 0 才算数
5. 思考部分写进同目录 `notes.md`
6. 跑通即提交（粒度见 `.claude/rules/git.md`）

## 切分粒度

**默认一题一脚本**，用注释分段对应 要求 / 思考 / 提高（不用 `%%`）。

例外：某道题的某一部分确实庞大、或需要独立可跑时，才拆成多个脚本。
具体留到读题时判断。

## 脚本命名（已定）

`hw<NN>_<行为名>.m`（例：`hw01_bouncingBall.m`），已写进 CLAUDE.md 的「脚本约定」。

保留 `hw<NN>_` 前缀的理由：作业目录名已含编号，但脚本被单独打开或拷走时，前缀仍能
自我标识。目录内不存在同名冲突，代价只是一个前缀。
